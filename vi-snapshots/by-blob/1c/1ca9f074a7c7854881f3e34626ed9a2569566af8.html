Test Launch For Nested Actor Without Caller.vi

Often you want to test a nested actor's behaviors without spinning up your full actor tree. You can write a test harness actor to use as a caller that will launch your nested actor, send it various test messages and monitor it for responses. Then you have to launch that test harness actor and somehow get the test results out of it. This VI allows you to easily get those test results. You pass an unlaunched test harness actor in and this VI sychronously launches and waits for the stop of that actor and returns to you the actor in its final state.

You can supply a <b>timeout in ms</b>. If the actor takes too long to run, it will be stopped with an Emergency Stop message; this VI will return error code 1639 indicating that a timeout occurred.

 Actor Before Launch

Open Actor Core front panel? (F)

Setting this input to true causes the Actor Core panel to open when it is called and close again when it finishes.

When debugging, this can be helpful as it gives you access to the Abort button for your actors and makes it easier to set probes/breakpoints on the particular instance of an actor that was just launched. Although good for debugging, using this input is generally a poor idea if you are actually planning to display the actor's panel in your finished code. Generally setting the properties for "Open when called" and "Close if originally closed" on the VI itself or having explicit Invoke Nodes for opening and closing the panel is a better solution since it guarantees that all the ways that the actor could be launched behave the same.
